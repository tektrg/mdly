# P0-1 — The asset GC deletes referenced images. Third time. Change the approach.

This bug has now been "fixed" three times along three different axes:

| Round | Axis fixed | What still deleted live images |
|---|---|---|
| 4 | structural path normalisation | folder not named `*.assets` |
| 5 | folder name + `#`/`?` encoding | **reference syntax** |
| — | | **non-canonical legacy rows** |

Round 5's matcher uses `visit(tree, "image")`, which only sees inline `![](…)`. Reproduced
end-to-end through the real upload + `POST /api/files` + real `runOrphanAssetCleanup`:

```
![a][id] + [id]: images/ref.png   -> refs found: []   -> DELETED from R2
![images/logo.png][]              -> refs found: []   -> DELETED
<img src="images/logo.png">       -> refs found: []   -> DELETED
first={marked:2} second={rowsDeleted:2, r2ObjectsDeleted:2}
```

`<img>` is routine in agent-generated Markdown. And the tombstone propagates to the desktop,
which deletes the user's **local original**.

## The rule

> **A deletion decision must fail toward keeping data.** Deriving "is this referenced?" by
> enumerating the syntaxes a reference *might* take is unbounded — every round finds another
> one. Derive it instead from a check that cannot miss: **does the raw note text contain this
> asset's path at all?**

Replace the AST-visitor reachability test with a **raw-content containment check** over every
live note's text, matching the asset path in its canonical form, its raw stored form, and its
percent-encoded form (and the `\`-to-`/` variant). A substring scan is syntax-agnostic: it
cannot be defeated by reference-style links, collapsed references, HTML `<img>`, `<a href>`,
CSS `url()`, front-matter, or any future syntax. It over-retains — a path mentioned in prose
keeps its asset alive — which is exactly the correct direction for a destructive operation.

Note the cost is fine: this is a nightly job over one workspace, not a hot path.

**Also fix the legacy-row axis in the same pass:** the matcher only ever emits canonical
paths, but `deleteAsset`'s own comment says non-canonical rows are "the expected production
state" from before round 4. Reproduced — 2 of 3 *referenced* rows tombstoned:
```
[{"path":"./images/x.png","deleted":true}, {"path":"images//y.png","deleted":true},
 {"path":"images/z.png","deleted":false}]
```
Canonicalise the **stored row path** before comparing, so a legacy row matches a canonical
reference.

**Required proof:** drive real uploads + real cron across the grace period for: inline,
reference-style, collapsed reference, shortcut reference, HTML `<img>`, `<a href>` to an
image, percent-encoded and angle-bracket forms, a path mentioned only in prose or a fenced
code block, and the three legacy non-canonical spellings above. **All must survive.** A
genuinely unreferenced asset — path appearing in no note at all — **must still be collected**;
prove the GC is not neutered.

# P0-2 — The pull side jams sync permanently. Blocker 2 is half fixed.

Round 5 capped uploads at 2MiB. The **download** path has the identical defect, and it is
reached far more easily — not by one large note, but by **~32MB of total workspace markdown**.

Server, measured by walking row count upward:
```
rows=16 approxMB=32 -> 200
rows=17 approxMB=34 -> 500 {"error":"Internal error."} + uncaught (in promise) Serialized RPC ... 34001847 bytes
```

Client: `backend.getFiles` is called **unguarded** in both `plan()` (`sync.ts:141`) and
`execute()` (`sync.ts:486`), and `execute()`'s call sits **before** `writeSyncState`
(`sync.ts:643`). Reproduced:
```
threw="Internal error."  pushed=["a.md","b.md","c.md"]  stateFiles=[]  lastSyncedAt=1 (unchanged)
```
Three files were pushed to the server, **zero recorded**, `lastSyncedAt` never advanced — so
every subsequent run re-pushes everything and fails identically. Permanent jam, same as the
push side. `getAssets` (`sync.ts:563`) has the same exposure.

## Required
1. **Server:** `getFiles`/`getAssets` must never attempt to return more than the RPC ceiling.
   Add cursor-based pagination with a bounded page size (by total bytes, not row count), and
   keep the existing `since` parameter working. No response may exceed a safe margin below
   32MiB, and no input may produce a 500 or an unhandled rejection.
2. **Client:** page through the listing. Guard every listing call. **A failure mid-run must
   never lose progress** — write sync state for everything that did succeed before propagating
   the error, so the next run resumes instead of repeating.
3. **Proof:** a workspace whose total markdown exceeds the old ceiling syncs completely across
   however many runs it takes, with `lastSyncedAt` advancing every run and no re-pushing of
   already-pushed files.
