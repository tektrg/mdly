## 1. HIGH — Path checks are bypassable; `../` traversal is stored

`assertCommentLogSlotInvariant` (`durableObject/files.ts:64-91`) matches `COMMENT_LOG_PATTERN`
against the path **exactly as the client sent it**. Anything not byte-identical falls through
`if (!match) return` and skips the check entirely. Proven over real HTTP:

| Path sent | Current result | Should be |
|---|---|---|
| `.mdly/comments/note.jsonl` | 403 blocked | 403 blocked |
| `./.mdly/comments/note.jsonl` | **200 written** | 403 blocked |
| `.mdly/comments/note.jsonl ` (trailing space) | **200 written** | rejected |
| `.mdly/comments/NOTE.JSONL` | **200 written** | 403 blocked |
| `../.mdly/comments/note.jsonl` | **200 written** | 400 rejected |

The last row is the worst: the server **persists a path that escapes the workspace root**.
This is pre-existing (single-file `pushFile` has it too) — fix BOTH paths, not just batch.

**Fix:** canonicalise every incoming file path at one chokepoint before any invariant check
or write. `normalizeWorkspacePath` already exists at `worker/orphanAssets.ts:122` and does
most of this (it returns `null` when the path escapes root) — export it into a shared module
and reuse it; do not write a second copy. It does NOT currently handle trailing/leading
whitespace in a segment, so add that. Reject with a 400 when it returns `null` or the path
is empty. Store and match the canonical form. Make the `.jsonl` extension match
case-insensitively.

Apply to: `pushFile`, `pushFilesBatch`, and `deleteFile` if it takes a path.

## 2. HIGH — A batch that fails halfway keeps files and tells nobody

`durableObject/workspaceDurableObject.ts` — the try/catch closes at the `toRpcError` return
(~line 200) and the write loop sits **outside** it (~202-207). Proven: a 4-file batch where
one file is 3MB returns **500**, but **2 files were already committed**, `bumpVersion` never
ran, and no broadcast fired. The server then holds notes no client believes it accepted —
and because the new `/api/version` poller sees an unchanged version, clients skip listing
files and never discover them.

**Fix:** make the batch atomic. Wrap the write loop + `bumpVersion` in
`this.ctx.storage.transactionSync(...)` so a mid-loop throw rolls the whole batch back, and
put it inside the error handling so the failure returns a proper typed error rather than an
uncaught 500. Only broadcast **after** the transaction commits. Verify the byte counter is
still exact after a rolled-back batch.

## 3. MEDIUM-HIGH — No byte limit on batch; fails as a 500 that leaks internals

Only a *file count* cap exists (`MAX_PUSH_BATCH_FILES`, checked inside the DO — last in the
path). 100 files x 1MB is within that cap and dies with a **500** leaking
`"Serialized RPC arguments ... 100006012 bytes"`.

**Fix:** add a total-bytes cap for a batch, well under the RPC limit (32MiB — use 8MB).
Enforce it in the Worker route **before** the RPC call, alongside the file-count cap, and
return **413** with a clean message. Keep the DO-side checks as defence in depth.

## 4. MEDIUM — The batch endpoint 413s on the bulk re-sync it exists for

The cap check sums every file's full `content.length` and ignores that most are overwrites.
Proven: re-pushing two unchanged 900KB files returns a spurious 413 on a net-zero write.

**Fix:** compute the incoming delta against the existing rows (sum of
`new length - old live length`, like `upsertFile` already does) rather than raw total.
Keep it an over-estimate if that's simpler to reason about, but it must not count bytes that
are being replaced.

## 5. MEDIUM — The auth regression test doesn't know about the new routes

`worker/auth.test.ts:11-66` — `API_ROUTES_BACKING_SYNC_BACKEND` is a hardcoded array whose
whole job is catching an unauthenticated route. It's missing `/api/files/batch` and
`/api/version`. Both ARE correctly gated today (confirmed by execution: no credential,
wrong bearer, garbage cookie -> six 401s) — but the test would not notice a regression.

**Fix:** add both routes to the array.

## 6. LOW — Empty batch gives a nonsense error
`files: []` throws `BatchTooLargeError(0, 100)` -> *"Batch of 0 files exceeds the maximum
batch size of 100 files - split it into smaller batches."* Give it its own error/message.
`batchVersion.test.ts:249` only asserts `status === 400`, so tighten that assertion too.

## 7. LOW — No type validation on request fields

reaches SQL. Validate shapes at the route boundary and 400 on bad input.
