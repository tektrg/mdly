## Background in one paragraph

Enabling cloud sync on a large folder (`~/01_Project/AptusFit`) froze the packaged Mac app for 221 seconds and it was killed. Root cause: every cost in the sync engine scales with workspace SIZE, not with amount of CHANGE. A hotfix already landed (commit `ace176c`) that excludes `.claude` and shares one ignore list between the watcher and the walker. This task is the structural follow-up.

## Scope — build in this order

### Phase 1 — engine: split sync into plan → execute (D-LW3)

In `packages/sync/src/sync.ts`, `sync()` currently decides and acts in the same loop, and returns counts only at the very end. Split it:

- `plan(backend, fs, workspacePath)` → `{ toPush, toPull, toDelete, conflicts }`, plus a **folder-grouped summary**: per folder `{ fileCount, bytes, autoExcluded?: "gitignored" | "nested-repo" | "over-threshold" }`.
- `execute(plan, onProgress)` → performs the work, calling `onProgress({ phase, done, total, currentPath })`.
- Keep the existing `sync()` as a thin wrapper over `plan()` + `execute()` so nothing that calls it today breaks.

**Throttle progress emission to ~100ms or every N files — NEVER per file.** This app was killed once already this week by an unthrottled event stream (765,000 editor transactions). Do not reintroduce that shape.

### Phase 2 — engine: cheap change detection

`FileStateSchema` in `packages/sync/src/types.ts` is `{ hash, lastSyncedAt }` — no mtime, no size. So "did this change?" can only be answered by reading and hashing every file, every cycle. Add `mtime` and `size`. Treat them as a HINT ("might have changed → verify by hashing"), never as proof — schema must stay backward-compatible with existing state files that lack the fields.

### Phase 3 — scope state (D-LW4 + D-LW5)

These two are ONE surface over ONE piece of persisted state — first sync IS the pending queue at t=0. Do not build them as two features.

- **Path-or-name exclusions.** `excludedFolders` today is a Set of folder NAMES matched at any depth (`isPrunedCloudSyncPath` in `apps/desktop/electron/cloudSyncWiring.ts`). A selection UI produces PATHS. Adopt gitignore's own convention in the same list: a bare name matches at any depth; an entry containing a separator is anchored to the workspace root. Built-in defaults stay name-based and unchanged.
- **Pending folders.** New folder with `>1000 files` OR `>N directories` → do not sync it, hold it pending. Persist `pendingFolders: [{ path, fileCountAtLeast, discoveredAt }]`. Three outcomes: `pending → approved | excluded (never ask again)`.
- **Count with an early bail at 1,001.** Never compute the exact number — "more than 1,000 files" is the whole message, and bailing keeps the safety check bounded.
- **The rest of the workspace keeps syncing while a folder is pending.** "Pending" scopes to that folder only, never the whole workspace.
- **Threshold must include directory count, not just file count.** Directories are what consume OS watch handles; 900 files across 4,000 folders is what kills the app. (The existing `SYNC_MAX_ENTRIES = 200_000` makes exactly this mistake — it counts entries when the constraint is directories.)

### Phase 4 — surfaces

- First-sync review dialog: folder-grouped checkbox tree, **auto-excluded folders shown greyed WITH their reason and still re-includable**.
- Settings: the pending-folders list with approve / never-ask-again.
- Status indicator in the main window: a passive badge when something is pending (Settings alone is somewhere you have to go look).
- Progress UI: indeterminate count-up during the walk (no total exists yet), determinate bar only after `plan()` returns. **No fake progress bar.**

The status channel today is `onCloudSyncStatusChange(status, detail)` — an 8-value enum plus a string. It cannot carry counts. It needs a structured payload.
